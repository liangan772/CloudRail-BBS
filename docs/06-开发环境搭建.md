# 06 开发环境搭建

## 1. 前提软件

| 软件 | 版本 | 用途 |
|------|------|------|
| Docker Desktop / Docker CE | 最新稳定 | 运行 Discourse（推荐方式） |
| Node.js | >= 20 | 前端 |
| pnpm | ^10 | 前端包管理（与 Discourse 前端一致） |
| Git | 任意 | 版本控制 |
| 可选：Ruby | ~> 3.4 | 仅 Discourse 源码方式 / 插件开发 |
| 参考源码 | `D:\discourse`（只读参考，勿改） | 查 API 实现、MessageBus 通道、插件 API |

> 当前工具链对 `D:\discourse` 为只读；插件开发阶段请把 Discourse 源码克隆为**可写副本**（建议放在本项目 `discourse/`，见第 5 节）。

## 2. 启动 Discourse（方式一：官方 Docker，推荐）

```bash
git clone https://github.com/discourse/discourse_docker.git /opt/discourse_docker  # 或 Windows 下任意目录
cd /opt/discourse_docker
cp samples/standalone.yml containers/app.yml
# 编辑 app.yml：设置 DISCOURSE_HOSTNAME（如 forum.test）、DISCOURSE_DEVELOPER_EMAILS、
# DISCOURSE_SMTP_*（邮件）、DISCOURSE_DB_PASSWORD、DISCOURSE_SECRET_KEY、DISCOURSE_ADMIN_EMAILS
./launcher bootstrap app      # 首次构建（约 10~30 分钟）
./launcher start app
```

- 容器内 Discourse 监听 80 端口；开发联调时映射到本机端口（如 `docker run -p 3001:80`，或改 app.yml 的端口映射）。
- 初始化：浏览器访问后按引导创建管理员；或 `./launcher enter app` 内执行 `rake admin:create`。
- 常用：`./launcher stop/start/restart app`、`./launcher enter app`、`./launcher logs app`。

## 3. 启动 Discourse（方式二：源码运行，插件开发用）

```bash
git clone https://github.com/discourse/discourse.git discourse
cd discourse
# 按 docs/02-development-environments 准备 PostgreSQL/Redis（Docker 或本机）
bundle install
bin/rails db:create db:migrate
bin/rails db:seed_fu
bin/dev    # 前端 Vite + 后端，默认 http://localhost:3000
```

## 4. 前端环境

```bash
cd web
pnpm install
cp .env.example .env    # 配置 NUXT_DISCOURSE_BASE 等
pnpm dev                # http://localhost:5173
```

Nuxt dev 代理（`nuxt.config.ts`），把系统路径转发到本地 Discourse：

```ts
routeRules: {},
nitro: {
  devProxy: {
    '/session':    { target: 'http://localhost:3001', changeOrigin: true },
    '/message-bus':{ target: 'http://localhost:3001', changeOrigin: true, ws: true },
    '/uploads':    { target: 'http://localhost:3001', changeOrigin: true },
    '/user-api-key': { target: 'http://localhost:3001', changeOrigin: true },
    '/raw':        { target: 'http://localhost:3001', changeOrigin: true },
    '/*.json':     { target: 'http://localhost:3001', changeOrigin: true },
  },
}
```

> 端口 3001 是 Discourse 容器映射出的本机端口（源码方式则为 3000）。代理规则与生产 nginx 保持一致（见 docs/02 §8）。

## 5. 联调检查清单

首次联调按序验证，全部通过后再开始功能开发：

1. `GET /site.json` 返回站点配置（代理与 CORS 正常）。
2. `GET /session/csrf.json` 获取 CSRF token，`POST /session` 登录成功，Cookie 写入。
3. 带 `X-CSRF-Token` 发帖成功，列表能看到新话题。
4. `POST /uploads.json` 上传图片并能在帖子中显示。
5. MessageBus 订阅 `/latest`，另开窗口发帖能实时收到事件（WebSocket 代理正常）。
6. 管理员账号可访问 `http://localhost:3001/admin`（内网后台）。

## 6. 种子数据

- 用管理员账号在 Discourse 后台创建分类：技术交流 / 生活闲聊 / 站务公告 等。
- 写一个前端侧种子脚本（`web/scripts/seed.mjs`）调用 API 生成 20~50 条示例话题/回复，便于开发与截图。
- 测试账号约定：`admin`（管理员）、`moderator`（版主）、`user1~user5`（普通用户）、`guest`（游客）。

## 7. 常用命令速查

| 场景 | 命令 |
|------|------|
| 前端启动 | `pnpm dev`（web/ 目录） |
| 前端类型检查 | `pnpm typecheck` |
| 前端 lint | `pnpm lint`（eslint + prettier） |
| 前端单测 | `pnpm test`（Vitest） |

## 8. 常见问题

| 现象 | 排查 |
|------|------|
| 前端请求 401/403 | 未带 CSRF token；Cookie 未同域（代理路径不匹配）；登录已过期 |
| WebSocket 连不上 | 代理缺 `ws: true` / nginx 缺 Upgrade 头；确认 `/message-bus` 可轮询（降级可用） |
| 上传 422 | `type` 参数缺失或不合法；未登录 |
| Discourse 启动失败 | `./launcher logs app` 看日志；确认 app.yml 的 DB 密码/域名配置 |
| 修改插件不生效 | 插件代码需重启服务；新增/删除文件后先 `rm -rf tmp` 再启动（Discourse 已知坑） |
| 中文用户名注册失败 | 未开启 `allow_unicode_usernames`（见 docs/05） |
