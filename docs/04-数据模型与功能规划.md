# 04 数据模型与功能规划

> Discourse 是**唯一数据源**：业务数据全部落在 Discourse 的 PostgreSQL，前端不建业务库。

## 1. 功能清单与优先级

优先级：P0 = MVP（M1）、P1 = M2、P2 = M3、P3 = 远期。

| 模块 | 功能 | 优先级 | 实现方式 |
|------|------|--------|----------|
| 账号 | 注册/登录/登出/激活/找回密码 | P0 | Discourse 原生（/session、/u） |
| 账号 | 头像、昵称、签名、个人资料 | P0 | Discourse 用户 API + 上传 |
| 内容 | 分类浏览、话题列表（最新/热门/新） | P0 | /categories.json、/latest.json 等 |
| 内容 | 话题详情、楼层、作者信息 | P0 | /t/{id}.json + /t/{id}/posts.json |
| 内容 | 发帖/回复/编辑/删除 | P0 | /posts.json、PUT/DELETE /posts/{id}.json |
| 内容 | Markdown 编辑器（预览） | P0 | vditor；正式渲染用 cooked |
| 搜索 | 全局搜索（词、@用户、#分类、标签） | P0 | /search.json |
| 搜索 | 中文分词优化 | P3 | 插件（n-gram/zhparser） |
| 社交 | 点赞、书签、@提及 | P1 | post_actions / bookmark API |
| 社交 | 私信（单聊/群聊） | P1 | archetype=private_message |
| 社交 | 关注分类/话题、静音 | P1 | notification level API |
| 实时 | 新帖/通知实时推送 | P1 | MessageBus |
| 编辑器 | 草稿自动保存/恢复 | P1 | /drafts.json |
| 图片 | 上传图片插入帖子/头像 | P1 | /uploads.json |
| 治理 | 举报、审核队列 | P2 | post_actions(flag) + /review.json（后台） |
| 治理 | 敏感词（替换/审核/屏蔽） | P2 | Discourse Watched Words（后台配置） |
| 治理 | 置顶/精华/关闭/归档 | P2 | PUT /t/{id}/status（版主） |
| 治理 | 封禁（silence/suspend）、管理员 | P2 | Discourse 后台 + 插件 API（如需） |
| 运营 | 站点统计/报表 | P2 | Discourse 后台报表；前端可选展示 /about.json 数据 |
| 扩展 | 用户/话题自定义字段 | P2 | 插件 register_*_custom_field |
| 扩展 | Webhook 异步事件（新帖/新用户等） | P2 | Discourse Webhooks → 自建回调服务 |

## 2. Discourse 数据模型 → 前端概念映射

| Discourse 模型 | 前端概念 | 关键字段（序列化器） |
|----------------|----------|----------------------|
| Category | 板块/分类 | id、name、slug、color、parent_category_id、description、topic_count、permission 相关 |
| Topic | 话题 | id、title、slug、category_id、archetype、created_at、views、like_count、post_count、tags[]、pinned、closed、archived、last_poster_username |
| Post | 帖子/楼层 | id、post_number、topic_id、username、created_at、cooked、raw（编辑时）、reply_to_post_number、likes、can_edit/can_delete |
| User | 用户 | id、username、name、avatar_template、bio、trust_level、admin/moderator、group_names、pending_count |
| Group | 组 | 权限组（管理员/版主/白名单组） |
| Notification | 通知 | id、notification_type、read、data(json)、created_at |
| Upload | 上传 | url、width、height、short_url、extension |
| Tag | 标签 | id、name、topic_count、staff 与否 |
| Reviewable | 审核项 | id、type、status、created_by、payload |
| Draft | 草稿 | draft_key、data、title、post_id、topic_id |
| PostAction | 点赞/举报 | post_action_type_id（2=点赞，3=举报） |
| Bookmark | 书签 | bookmarkable 对象、reminder_at |
| PrivateMessage | 私信 | archetype=private_message + target_usernames |

> 字段全集以各端点实际 JSON 为准；前端 `api/types/` 按真实响应维护，不照抄文档。

## 3. 关键站点设置（中文论坛推荐配置）

以下在 Discourse 管理后台 → 设置中配置（设置名以实际版本为准，后台可搜索）：

| 设置 | 推荐值 | 说明 |
|------|--------|------|
| default_locale | zh_CN | 站点默认中文 |
| title / company_name | 站点名/品牌 | 显示名与邮件署名 |
| allow_unicode_usernames | true | **允许中文用户名**（论坛刚需） |
| 头像相关 | 关闭 Gravatar、允许本地上传 | 国内访问 Gravatar 不稳定 |
| max_topic_title_length | 60–100 | 中文标题较短，可下调 |
| min_post_length / min_topic_title_length | 按内容调 | 防灌水与空帖 |
| login_required | false | 游客可读（利于 SEO 与引流） |
| invite_only | false | 开放注册（可配合审核） |
| 新用户发帖限制 | 按信任等级默认 | 防垃圾（trust level 0 约束） |
| 敏感词（Watched Words） | 自定义词库 | 替换/审核/屏蔽三类动作 |
| 审核策略（approve_* 系列） | 按需开启 | 新用户首帖需审核等 |

## 4. 权限模型（前端如何判断"能不能"）

- Discourse 用 Guardian 做权限判定，前端**不要自己推断权限**：
  - 列表/详情 API 返回的 `details.can_edit`、`can_delete`、`can_create_topic`、`can_reply` 等字段是唯一依据。
  - 按钮按这些字段显示/隐藏；越权请求由服务端 403 兜底（前端同时做错误处理）。
- 信任等级（trust_level 0–4）影响发帖频率、编辑时限等，前端可据此展示徽章/限制提示。
- 组权限：分类可对组开放/私密；私密分类的话题列表对无权限用户返回 404/403，前端做兜底页。

## 5. 内容治理流程

```
用户举报(flag) → Discourse reviewable 队列 → 管理员/版主在 Discourse 后台处理
（同意→删除/警告/封禁；拒绝→忽略）  ← 前端提供"举报"入口与反馈状态
敏感词命中 → 替换 / 进入审核 / 屏蔽（后台词库管理）
```

- 前端只实现入口（举报按钮 + 原因）与状态展示（已处理/待处理），**处理动作全部在 Discourse 后台**（M3 阶段）。
- 紧急治理（删除、封禁）依赖版主及时登录后台；如需从前端触发，做插件 API（见 §7）。

## 6. 自定义字段与扩展（插件规划）

候选扩展，按需开发（开发规范见 discourse-dev 技能）：

| 需求 | 实现 | 要点 |
|------|------|------|
| 用户资料扩展（如"个人简介/所在城市"） | 插件 `register_user_custom_field_type` + `allow_public_user_custom_field` + `add_to_serializer :user` | 前端 /u/{name}.json 读取 |
| 话题扩展（如"悬赏/状态"） | `register_topic_custom_field_type` + add_to_serializer | 前端 /t/{id}.json 读取 |
| 前端触发管理操作（如需） | Rails Engine 控制器 + 挂载路由 + Guardian 校验 | 见 discourse-dev 技能 §6.3 |
| 中文搜索增强 | 迁移 + n-gram 分词（pg_bigm/zhparser） | 列为 P3 待办，先做可行性验证 |
| 异步事件消费 | Discourse Webhook（post_created、user_created 等） | 自建回调服务，幂等处理 |

**插件开发前置条件**：在可写的 Discourse 源码副本中开发（docs/06 §2），插件目录 `plugins/<name>/`，`plugin.rb` 为存在标志；改动后需重启服务，新增/删除文件后先 `rm -rf tmp`。

## 7. 已知待验证项（开发期确认）

1. 中文搜索质量与优化方案可行性（zhparser 在官方 Docker 内的安装）。
2. MessageBus 各通道名称以 `grep -rn "MessageBus.publish" <discourse源码>/app` 为准。
3. 少量端点（书签、reviewable 处理、admin users）的精确参数以实测为准。
4. 邮件发送走国内 SMTP 服务的连通性与发信限制。
