# 01 项目概述与技术选型

## 1. 项目定位

开发一个中文社区论坛，面向中文用户群体，覆盖发帖、回复、搜索、通知、私信、内容治理等论坛核心能力。

两个核心约束：

1. **前端自主开发**：使用 HTML/JavaScript 及现代前端框架（Vue 生态），不采用 Discourse 自带的 Ember 前端。
2. **后端复用 Discourse**：以 Discourse 为业务后端，不重复造轮子（用户体系、帖子/话题、权限、审核、邮件、搜索、限流、防灌水等都是成熟能力）。

## 2. 为什么用 Discourse 做后端

| 能力 | Discourse 提供 | 自研成本 |
|------|----------------|----------|
| 用户体系（注册/登录/邮箱激活/找回密码） | 完整，含限流与防滥用 | 高 |
| 话题/帖子/分类/标签/私信/草稿 | 完整数据模型与 API | 高 |
| 权限模型（信任等级、组、版主/管理员） | Guardian 体系，成熟 | 高 |
| 内容审核（举报、审核队列、敏感词、封禁） | 内置 reviewable 机制 | 高 |
| 实时推送（新帖/通知） | MessageBus（Redis pub/sub + WebSocket） | 中 |
| 全文搜索 | PostgreSQL 全文检索 | 中 |
| 邮件通知、Webhook | 内置 | 中 |
| 反垃圾（限流、新用户约束） | RateLimiter + 信任等级 | 高 |

风险与对策见第 5 节。

## 3. 功能范围

### 3.1 MVP（里程碑 M1，见 docs/09）

- 注册 / 登录 / 登出 / 邮箱激活 / 找回密码
- 首页话题列表（最新 / 热门 / 新帖）
- 分类浏览与话题列表
- 话题详情（帖子分页、楼层、作者信息）
- 发帖 / 回复 / 编辑 / 删除自己的帖子
- Markdown 编辑器（中文友好，预览模式）
- 全局搜索（关键词 + @用户 + #分类 + 标签）
- 用户主页（资料、发帖记录、回帖记录）
- 通知列表（轮询版）
- 头像上传

### 3.2 体验增强（里程碑 M2）

- 实时通知与新帖（MessageBus WebSocket）
- 点赞 / 取消点赞、书签、@提及
- 私信（一对一、群组私信）
- 图片上传与插入
- 草稿自动保存与恢复
- 关注/静音分类与话题

### 3.3 社区治理（里程碑 M3）

- 版主 / 管理员权限流转（复用 Discourse 后台）
- 举报与审核队列、敏感词
- 置顶 / 精华 / 关闭 / 归档
- 用户封禁（silence / suspend）、IP 限制
- 站点统计与报表（Discourse 后台 + 前端展示精简版）

## 4. 技术选型

| 层 | 选型 | 理由 |
|----|------|------|
| 前端框架 | **Nuxt 3**（Vue 3 + Vite + TypeScript） | SSR 利于论坛 SEO；Vue 中文资料/人才多；Nuxt 自带路由、服务端、环境配置 |
| 状态管理 | Pinia | Vue 3 官方推荐，类型友好 |
| i18n | @nuxtjs/i18n（vue-i18n） | 简体中文默认，预留繁体/英文 |
| 样式 | UnoCSS / Tailwind + CSS 变量（深浅色主题） | 原子化快速迭代；论坛前台样式自研，不引入重组件库 |
| 组件库 | 前台自研 + 少量 Element Plus（后台型页面） | 保证论坛视觉独特性；后台页面用现成组件提速 |
| Markdown 编辑器 | vditor（中文界面，分屏/所见即所得）；备选 md-editor-v3 | 中文论坛标配编辑器；正式内容一律渲染 Discourse 服务端 `cooked`（已消毒），编辑器只负责输入与预览 |
| 构建/包管理 | Vite + pnpm（^10，Node >= 20） | 与 Discourse 前端工具链一致，开发者切换仓库无负担 |
| 后端 | **Discourse**（Ruby ~3.4 / Rails ~8.0，PostgreSQL + Redis + Sidekiq） | 唯一数据源；部署用官方 Docker（discourse_docker / launcher） |
| Discourse 版本策略 | 生产跟随**最新 ESR**（如 2026.7），或 ESR 之后的首个稳定版；每月小版本不追 | 官方 ESR 每约 6 个月一个，支持窗口稳定（`versions.json`） |
| 反向代理 | nginx（TLS 终结、路径分流、WebSocket 升级） | 同域架构的核心（见 docs/02） |
| 测试 | Vitest + Playwright（前端）；RSpec / QUnit（若开发 Discourse 插件） | 见 docs/07 |
| 部署 | Discourse 官方 Docker + Nuxt 容器（或 PM2）+ nginx | 与官方升级路径一致，见 docs/08 |

## 5. 关键取舍与风险

| 取舍/风险 | 说明 | 对策 |
|-----------|------|------|
| Discourse API 覆盖面 | API 覆盖核心读写，但少量管理动作（如部分后台配置）没有公开端点 | 管理动作走 Discourse 自带后台；缺失能力用**插件扩展**（Rails Engine 控制器 + `add_to_serializer` 等，见 docs/02 §7） |
| 自定义前端与 Discourse 路由冲突 | Discourse 原生页面路径（/t/、/c/）与前端路由可能撞车 | 采用"单域名白名单反代"：前端拥有全部用户可见路由，nginx 仅把系统路径转发给 Discourse（docs/02 §2、§8） |
| 中文全文搜索效果 | PostgreSQL 默认分词对中文支持有限 | MVP 用 Discourse 搜索（标题/内容简单分词）；M3+ 评估插件引入 n-gram / zhparser 优化（docs/04 §7 待办） |
| 双套 UI 维护 | 管理员用 Discourse 原生后台，用户用自研前端，两套界面 | 明确边界：前台全自研，后台复用 Discourse，不做自研管理后台（MVP） |
| Discourse 升级兼容 | 大版本升级可能影响 API/设置项 | 固定 ESR 版本，测试环境先行，升级前完整备份（docs/08 §4） |
| 大陆合规 | 论坛需 ICP 备案、公安备案、实名制与内容审核义务 | 提前启动备案流程，合规清单见 docs/08 §6 |

## 6. 术语约定

- **前端 / web**：自研 Nuxt 应用，位于 `web/`。
- **后端 / Discourse 实例**：论坛业务后端，Docker 部署。
- **系统路径**：由 nginx 转发给 Discourse 的路径白名单（/session、/message-bus、/uploads、*.json 等）。
- **cooked**：Discourse 服务端渲染并消毒后的帖子 HTML，前端直接展示。
