# 03 前端工程规范

## 1. 技术栈

| 项 | 选型 | 说明 |
|----|------|------|
| 框架 | Nuxt 3（Vue 3 组合式 API + Vite） | SSR 渲染，论坛 SEO 必需 |
| 语言 | TypeScript（严格模式） | API 数据有 Discourse 序列化器结构，类型化收益大 |
| 状态管理 | Pinia | store 划分见 §5 |
| i18n | @nuxtjs/i18n | 默认 `zh-CN`，见 docs/05 |
| 样式 | UnoCSS + CSS 变量 | 深浅色主题用 CSS 变量切换 |
| 组件库 | 前台自研组件；Element Plus 仅用于后台型页面 | 不整库引入，按需 |
| Markdown 编辑器 | vditor（推荐） | 中文界面；仅负责输入与预览 |
| HTTP | ofetch（Nuxt 内置）/ ky | 统一封装在 `api/` 层 |
| 实时 | message-bus-js | 同域连接 Discourse MessageBus |
| 代码质量 | ESLint + Prettier + vue-tsc + Husky + commitlint | conventional commits |

环境要求：Node >= 20，pnpm ^10（与 Discourse 仓库工具链一致）。

## 3. API 客户端层（关键）

所有 Discourse 请求**必须**经过 `api/client.ts`，禁止在组件里散落裸请求。

```ts
// api/client.ts 核心职责
// 1. baseURL：同域直连（默认 ''，走 nginx）；开发环境走 vite 代理
// 2. 自动附带会话凭证（同域 cookie，浏览器自动携带）
// 3. 请求拦截：除 GET/HEAD 外自动附带 X-CSRF-Token（来自 /session/csrf.json，登录后获取）
// 4. 响应拦截：
//    - 401 → 跳登录页（保留 return_path）
//    - 403/404/422 → 归一化为 ApiError{ status, errors[] }
//    - 429 → 读取等待提示，展示"操作过于频繁，请稍后再试"
// 5. 类型：每个端点对应 types/ 下的接口，命名与 Discourse 序列化器字段一致
```

要点：

- **CSRF**：cookie 会话下，写操作需 `X-CSRF-Token`（见 docs/02 §4）。Token 登录后缓存，失效（401）时重新拉取。
- **分页**：列表接口返回 `topic_list.more_topics_url` / `more_posts_url` 等；滚动加载直接请求该 URL，不自行拼参数。
- **错误展示**：`errors[]` 数组逐条展示；Discourse 的错误文案多为英文，前端做映射表翻译（docs/05 §3）。
- **契约测试**：`api/` 层写集成测试打真实实例（docs/07 §2）。

## 4. 页面与路由约定

- 使用文件路由；动态段命名：`/t/[id].vue`、`/c/[slug]-[id].vue`、`/u/[username].vue`。
- 保持 `/t/:id`、`/c/:slug/:id` 与 Discourse 邮件链接的路径形状一致，避免用户点击邮件链接 404（docs/02 §8）。
- 路由守卫统一处理：登录态（useCurrentUser）、管理员页（`/admin` 只读展示部分统计，管理操作在 Discourse 后台）。

## 5. 状态管理（Pinia）

| store | 内容 | 生命周期 |
|-------|------|----------|
| `session` | 当前用户、登录态、CSRF token | 应用级；SSR 端从 `/session/current.json` 初始化 |
| `site` | /site.json（分类树、表情、默认设置） | 缓存 + `/categories` 通道失效 |
| `topicList` | 各列表页数据与分页游标 | 页面级 |
| `composer` | 编辑器状态（草稿 key、内容、附件） | 会话级；草稿落 Discourse |
| `notifications` | 通知列表、未读数 | 订阅 `/notification`、`/unread` |
| `realtime` | MessageBus 连接状态与订阅管理 | 应用级单例 |

原则：服务端数据不复制到多份 store；列表数据组件局部持有，store 只放跨页共享状态。

## 6. 组件规范

- 组合式 API；`defineProps` + `defineEmits` 显式声明；`<script setup lang="ts">`。
- 命名：目录小写中划线（`topic-list-item.vue`），组件名 PascalCase 引用。
- 无状态纯展示组件不放业务逻辑；页面只做编排，数据获取放 composables。
- 帖子正文渲染：`<div v-html="post.cooked">`，**只渲染服务端 cooked**，不渲染任何客户端 markdown 产物。
- 可访问性：语义化标签、键盘可达、图片 alt；中文论坛注意字号 ≥ 14px、行高 1.6+。
- 深浅色主题：所有颜色走 CSS 变量（`--c-bg`、`--c-text`、`--c-primary`…），不硬编码色值。

## 7. i18n 与文案

- 所有用户可见文案进 `locales/zh-CN.yml`，禁止硬编码中文串。
- key 命名：`页面.模块.动作`（如 `topic.post.reply`）。
- Discourse 返回的错误/提示文案做映射表（docs/05 §3），未覆盖的兜底显示原文。
- 语气：中文社区风格，简洁、礼貌、无翻译腔。

## 8. 代码质量与提交

- `pnpm lint`（ESLint + Prettier）、`pnpm typecheck`（vue-tsc）作为本地与 CI 门禁。
- Husky pre-commit：lint-staged（lint + format）；commit-msg：commitlint 校验 conventional commits（`feat/fix/docs/refactor/test/chore`）。
- 提交信息示例：`feat(topic): 支持楼层跳转`；PR 标题同规范（docs/09 §4）。

## 9. 性能基线

- SSR 首屏：首页 TTI < 2.5s（国内普通网络）；话题详情页首屏内容 < 1.5s。
- 列表页虚拟滚动（帖子很多时）；图片懒加载（`loading="lazy"`），头像用 Discourse 优化尺寸 URL。
- 分包：按路由自动分包；vditor 按需加载（仅编辑器页）。
- 缓存：`/site.json`、分类树本地缓存；API GET 请求开启 stale-while-revalidate 策略（列表类）。
- 移动端：响应式布局为第一公民（论坛大量移动访问），断点 640/1024/1280。

## 10. SSR 注意事项

- 不要在服务端直接访问浏览器 API（localStorage、WebSocket）；MessageBus 只在客户端挂载后连接。
- SSR 端请求 Discourse 用服务端 fetch（同域内网），注意超时与降级：Discourse 不可用时首页可降级为静态壳 + 错误提示。
- `useCurrentUser` 在 SSR 端注入首屏用户态，避免登录后闪烁。
