# 05 中文支持与本地化

## 1. Discourse 侧（后端）

| 项 | 配置/做法 |
|----|-----------|
| 站点语言 | 站点设置 `default_locale = zh_CN`（Discourse 内置简体中文 locale） |
| 中文用户名 | 开启 `allow_unicode_usernames`，否则中文用户名无法注册 |
| 中文标题 | 按需调大 `max_topic_title_length`（默认约 80 字符，中文建议 60~100，需实测） |
| 头像 | 关闭 Gravatar 相关设置（国内不可达），允许本地上传头像（`allow_uploaded_avatars`），注册引导用户上传 |
| 时区/日期 | 站点时区设为 `Asia/Shanghai`，前端展示统一用本地时区格式化 |
| 邮件 | SMTP 使用国内可达服务（阿里云邮件推送等），发件文案可在管理后台覆盖为中文 |

> 具体设置名以部署实例的 `管理后台 → 设置` 为准（不同版本名称有差异）。

## 2. 前端 i18n

- 使用 `@nuxtjs/i18n`（vue-i18n），**默认简体中文**；locale 结构预留 `zh-TW`、`en`。
- 文案规范：
  - 所有用户可见字符串必须走 i18n key，禁止硬编码中文（便于后续多语言与审校）。
  - key 按页面/组件域组织：`topic.list.title`、`composer.placeholder`、`user.profile.edit`。
  - 动态文案用占位符（`{name}`），禁止字符串拼接。
- 与 Discourse 文案对齐：Discourse 内置 zh_CN 翻译可作术语参考（如「话题/帖子/分类/私信」），保持前后端术语一致。

## 3. 中文体验细节

- 字数统计按**字符数**（中英文混合），发帖最小长度设置需适配中文（`min_post_length` 默认值对中文偏严可下调，实测）。
- 编辑器：vditor 中文界面；自动空格、引号、全角标点等体验在 M1 后打磨。
- 搜索输入：中文输入法组合期间不触发搜索（防抖 + `compositionstart/end` 处理）。
- 列表时间显示：`X 分钟前 / 昨天 / 2026-08-16` 中文相对时间。

## 4. 中文搜索（已知短板与对策）

- Discourse 搜索基于 PostgreSQL 全文检索，**对中文切词效果有限**（整句/大词匹配）。
- MVP：直接使用 `GET /search.json`（标题、全文简单匹配可用，配合 `#分类 @用户 tag:` 语法）。
- M3+ 优化候选（择一，需先在测试环境验证）：
  1. Discourse 插件引入中文分词（如 zhparser / pg_bigm 扩展 + 自定义 tokenizer）；
  2. 自建轻量搜索索引（前端侧服务定期拉取话题/帖子增量，用中文分词器，如 jieba 系）——数据同步走 Webhook（docs/02 §7）；
  3. 接第三方搜索服务（需评估成本与合规）。
- 决策前先做搜索质量评估用例集（10~20 个中文查询），量化对比后再投入。

## 5. SEO（中文站点）

- Nuxt SSR：`useHead` 输出 title/description/OG/JSON-LD（`BreadcrumbList`、`DiscussionForumPosting`）。
- 规范 URL：前端自建 `sitemap.xml`（按分类/话题分页生成，nginx 直接服务）；Discourse 自带 sitemap 不对外。
- URL 风格：`/t/{id}` 或 `/t/{slug}-{id}`（与 Discourse 一致，利于分享识别）；列表 `/c/{slug}`、`/latest`、`/top`。
- 中文 title 长度控制（百度约 30 字内截断）；`<html lang="zh-CN">`。
- 移动端适配 + `viewport`；图片 `loading="lazy"` + 尺寸属性（避免 CLS）。

## 6. 内容规范与社区公约

- 编写《社区公约》（注册时勾选），覆盖：禁止违法信息、侵权、广告、人身攻击；举报与处罚说明。
- 敏感词：Discourse 管理后台「审查词」（watched words）配置 替换/审核/屏蔽 动作。
- 违法信息举报入口（前台显眼位置 + 管理员处置），满足《互联网论坛社区服务管理规定》义务（详见 docs/08 §6）。
