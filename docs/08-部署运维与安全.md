# 08 部署、运维与安全

## 1. 生产拓扑

```
用户 ── CDN/WAF(可选) ── nginx (forum.example.com:443, 境内服务器)
                            ├── / 前端路由        → Nuxt SSR（容器，127.0.0.1:3000）
                            ├── 系统路径与 *.json → Discourse 容器（127.0.0.1:3001，仅内网）
                            │      /session /user-api-key /message-bus /uploads /raw /srv
                            └── /admin             → 仅内网 IP / 管理员白名单

Discourse 容器（discourse_docker，官方镜像）内：
   Rails/Puma + Sidekiq + PostgreSQL + Redis
前端容器（node:20-alpine + PM2 或 node server）：
   Nuxt SSR 无状态；静态资源可上国内 CDN
备份：Discourse 自带备份（每日，S3/本地异地）；前端无状态无需备份
```

nginx 关键配置（与开发代理保持一致）：

```nginx
server {
  listen 443 ssl http2;
  server_name forum.example.com;
  # TLS 证书、HTTP→HTTPS 跳转、安全响应头（HSTS/CSP 等）省略

  location / { proxy_pass http://127.0.0.1:3000; }        # Nuxt SSR

  # Discourse 系统路径白名单
  location ~ ^/(session|user-api-key|message-bus|uploads|raw|srv|email|u/activate-account|u/confirm-|letter_avatar|user_avatar|secure-media-uploads)/ {
    proxy_pass http://127.0.0.1:3001;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-Host $host;
    proxy_http_version 1.1;                       # WebSocket 支持
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
  }
  # JSON API
  location ~* \.json$ { proxy_pass http://127.0.0.1:3001; proxy_set_header Host $host; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; proxy_set_header X-Forwarded-Proto $scheme; }
  # 管理后台仅内网
  location /admin { allow 内网网段; deny all; proxy_pass http://127.0.0.1:3001; }
}
```

要点：

- Discourse 的 `DISCOURSE_HOSTNAME` 必须设为**公开域名**（与 nginx 一致），否则生成的链接/图片 URL 会指向错误主机。
- 其余 Discourse 原生页面路径（/t/、/c/、/latest 等）**不代理**，由前端路由接管；邮件链接打到这些路径时由 SPA 渲染对应页面。
- WebSocket 走 `/message-bus`，nginx 需 Upgrade 头；断线时前端降级为轮询（MessageBus 自带）。

## 2. 部署与发布

- **Discourse**：官方 `discourse_docker`（launcher）。`app.yml` 关键项：`DISCOURSE_HOSTNAME`、`DISCOURSE_DEVELOPER_EMAILS`、`DISCOURSE_SMTP_*`、`DISCOURSE_DB_PASSWORD`、`DISCOURSE_SECRET_KEY`、worker 数按内存调整。升级 = `./launcher rebuild app`（先备份，测试环境先行）。
- **前端**：`pnpm build` → 镜像（node:20-alpine，`node .output/server/index.mjs`）→ 容器编排（docker compose 或单机 systemd/PM2）。配置经环境变量注入（Discourse 地址、CDN 域名等），构建产物不携带密钥。
- **发布流程**：见 docs/09 §6（灰度、回滚）。

## 3. 监控与告警

| 项 | 手段 |
|----|------|
| 站点可用性 | 外部探针（UptimeRobot 等）+ `/srv/status.json` |
| 应用日志 | 前端/Discourse 日志统一采集（文件 + 可选 Loki/ELK）；错误率告警 |
| Discourse 健康 | `./launcher logs app` 关注 Sidekiq 队列积压、Redis/PG 连接 |
| 资源 | 服务器 CPU/内存/磁盘/带宽告警（磁盘满是最常见故障） |
| 性能基线 | 首页 p95 响应时间，周报比对 |
| 安全事件 | 登录失败聚合、异常上传量、管理员操作审计（Discourse 自带） |

## 4. 备份与升级

- 备份：Discourse 管理后台「备份」，每日 + 发版前手动；存本地 + 异地（S3/另一台机器）。恢复演练每季度一次。
- 升级节奏：跟随 ESR（如 2026.7 → 2026.13 …），每半年左右升级一次；小版本（安全修复）按官方公告评估。
- 升级流程：测试实例升级 → 契约测试/回归 → 生产备份 → 生产升级 → 观察 24h。
- Discourse 版本支持窗口以官方 `versions.json` 为准；不要长期停留在 EOL 版本。

## 5. 安全清单

- HTTPS 全站（TLS 1.2+，HSTS）；HTTP 跳转 HTTPS。
- CSP 响应头：允许自域、CDN 域；`/message-bus` WebSocket 域白名单（Discourse 的 CSP 默认允许同源）。
- 会话安全：Discourse Cookie HttpOnly + SameSite=Lax（同域架构天然安全）；管理员开启 2FA。
- CSRF：所有写操作带 `X-CSRF-Token`（见 docs/02 §3），前端拦截器统一注入。
- XSS：只渲染 `cooked`；编辑器预览用 vditor 自带消毒；禁止 `v-html` 直接输出用户内容。
- 上传：沿用 Discourse 类型/大小/图片重编码限制；上传域名与站点同域，避免图片外链盗刷（后续可加 CDN + 防盗链）。
- 依赖安全：`pnpm audit` 入 CI；关注 Discourse 安全公告。
- 运维安全：SSH 密钥登录、防火墙只开 80/443/22(白名单)、数据库不暴露公网、管理员后台 IP 白名单。
- 服务器与数据：位于**境内**（合规与访问速度），系统盘/数据盘加密可选。

## 6. 中国大陆合规清单（论坛）

> 以下为通用要求梳理，**以最新法规与专业法务意见为准**，上线前逐项确认。

| 项 | 要求 | 状态 |
|----|------|------|
| ICP 备案 | 域名 + 境内服务器必须 ICP 备案（服务商处办理），备案号展示在页脚 | 提前启动（周期 2~4 周） |
| 公安备案 | ICP 备案后 30 日内到全国公安备案系统办理，页脚展示备案号 | 同上 |
| 实名制 | 《互联网论坛社区服务管理规定》：用户**后台实名、前台自愿**（手机号/身份证实名认证机制） | 需在 M3 前接入实名方案（短信验证码注册即可满足"后台实名"主流做法） |
| 内容审核 | 建立内容审核制度（审核人员、敏感词、举报通道、24h 处置响应） | 敏感词 + 举报 + 审核队列（Discourse 原生）+ 值班制度 |
| 隐私保护 | PIPL：隐私政策、单独同意、数据最小化、删除权响应（用户注销） | 上线前出隐私政策；Discourse 支持用户删除本人数据 |
| 未成年人 | 未成年人注册需监护人同意（14 周岁以下一般需父母同意） | 注册流程加年龄确认与家长同意条款 |
| 增值电信许可 | 若论坛**经营性收费**（会员付费等），需 ICP 经营许可证；免费社区一般 ICP 备案即可 | 确定商业模式后评估 |
| 网络安全 | 等级保护（非强制但对公网论坛建议）、安全事件报告义务 | 上线后按需 |

## 7. 应急预案

1. **站点不可用**：检查 nginx → Discourse 容器 → 磁盘/内存；`./launcher restart app`；回滚前端到上一版本（镜像 tag）。
2. **数据异常/误删**：从备份恢复（先只读挂载验证）；Discourse 管理员有回收站机制（软删除）。
3. **被攻击**：登录限流已默认开启；异常时先封 IP（防火墙）+ 查看审计日志；必要时联系服务器商。
4. **内容违规被通报**：立即下架 + 留存证据 + 按规定报告；平时保持审核值班。
5. 值班联系方式与操作手册成文，随 docs/ 一起维护。
