# 07 测试与质量保障

## 1. 测试分层

```
E2E（Playwright，关键用户路径）        ← 少量、慢、贵
API 契约/集成测试（对真实 Discourse）  ← 核心，防止前后端契约漂移
组件测试（Vue Test Utils）            ← 交互逻辑
单元测试（Vitest）                    ← API 客户端、store、composable、工具函数
Lint / 类型检查（ESLint + tsc）        ← 每次提交
```

## 2. 前端测试

| 层 | 工具 | 覆盖对象 | 示例 |
|----|------|----------|------|
| 单元 | Vitest | `web/api/` 客户端（URL、参数、错误归一化）、stores、composables、i18n 工具 | 429 处理、分页参数、CSRF 注入 |
| 组件 | Vue Test Utils | 编辑器、话题卡片、通知列表等交互组件 | 点赞按钮状态切换、表单校验 |
| E2E | Playwright | 关键路径（见下） | 注册→发帖→回复→点赞→搜索→通知 |

E2E 关键路径（P0）：

1. 游客浏览首页/话题列表 → 点话题查看详情。
2. 注册（邮箱激活流程）→ 登录 → 发新话题 → 回复 → 编辑 → 删除。
3. 搜索关键词、`#分类`、`@用户`。
4. 上传图片插入帖子。
5. 通知出现与已读。
6. 未登录访问发帖/设置 → 跳转登录页。

E2E 运行前提：一个干净的 Discourse 测试实例（Docker，`web/.env.e2e` 指向它），Playwright 配置 `webServer` 先起 Nuxt，`globalSetup` 重置测试数据（脚本调用管理 API 清理并重建种子数据）。

## 3. API 契约测试（重点）

Discourse API 会随版本演进，前端必须尽早发现契约变化：

- 为 `web/api/` 每个模块建契约测试：调用真实 Discourse 实例，断言响应结构（字段存在、类型、关键值），并保存响应快照。
- 每月 Discourse 版本升级后（或升级前在测试实例验证），全量跑契约测试比对差异。
- 对不稳定的字段（`details.can_*` 权限字段、`post_stream` 分页）单独断言，避免静默破坏。
- 测试账号：专用 API 测试用户 + 测试分类，禁止污染生产数据。

## 4. Discourse 侧测试（仅插件开发时需要）

| 类型 | 命令 | 说明 |
|------|------|------|
| 后端 RSpec | `bin/rspec spec/...` | 插件 `plugins/<name>/spec/`；行为优先、用 `fab!`、断言公共边界 |
| 前端 QUnit | `bin/qunit frontend/...` | 插件 `plugins/<name>/test/` |
| Lint | `bin/lint --fix` | eslint + prettier + stylelint，提交前必跑 |
| 迁移 | 写迁移前读官方技能 `discourse-migration` | 已发布迁移不可改；大表操作放 post_migrate |

## 5. CI 门禁（GitHub Actions / GitLab CI）

流水线（全部通过才允许合并）：

1. `lint`（eslint + prettier + vue-tsc 类型检查）
2. `test:unit`（Vitest）
3. `test:e2e`（Playwright，起临时 Discourse 容器）
4. `build`（Nuxt 生产构建）
5. 可选：`test:contract`（对 staging 实例跑契约测试）

质量红线：

- 主分支不允许 `pnpm lint` / `typecheck` / 单测失败。
- 覆盖率目标：`api/` 层 >= 80%，整体 >= 60%（新代码必须带测试，评审强制）。
- E2E 关键路径失败即阻断发版。
- 生产代码禁止 `console.log` 残留、禁止 TODO 阻塞项上线（评审把关）。

## 6. 性能与安全测试

- 性能：首页/列表/话题详情 SSR 响应时间基线（目标 p95 < 800ms 内网实测）；图片懒加载与尺寸属性；列表接口分页上限压测（`siege`/`k6` 选一，M4 前做一次）。
- 安全：OWASP 基础项走查——XSS（cooked 消毒、禁止前端渲染用户 Markdown）、CSRF（token 全覆盖）、上传类型/大小白名单（Discourse 默认限制）、登录爆破（Discourse 限流默认开启）、依赖漏洞扫描（`pnpm audit` + Discourse 升级公告）。
- 合规自检：敏感词生效、举报通道可用、隐私政策可访问（见 docs/08 §6）。
